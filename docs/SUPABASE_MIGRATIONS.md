# Supabase migrations

Two Supabase projects are used: one for development (Preview / local) and one for production. Apply the same schema to both. See [ENVIRONMENTS.md](ENVIRONMENTS.md) for which project each environment uses.

## New project (no schema yet)

1. Open the Supabase project in the Dashboard → SQL Editor.
2. Run `database/bootstrap.sql` once. Paste the file contents and execute.

`database/bootstrap.sql` is the concatenation of all files in `database/migrations/` in numeric order. It is generated by `make db-bootstrap`. Do not edit it by hand. After adding a new migration, run `make db-bootstrap` and commit the updated bootstrap so new projects get the latest schema.

**Do not run bootstrap on a project that already has these tables.** It uses plain `CREATE TABLE` (no `IF NOT EXISTS`) and will error with "relation … already exists".

## Existing project (schema already applied)

Run only **new** migration files—those not yet applied—in numeric order from `database/migrations/`. Copy each file’s contents into the SQL Editor and execute. Repeat for the other project (dev and prod) so both stay in sync.

### Reload API schema cache after migrations

The Supabase API (PostgREST) caches the database schema. After running migrations or bootstrap in the SQL Editor, refresh the cache:

```sql
NOTIFY pgrst, 'reload schema';
```

Then retry the request.

## Adding a new migration

1. Add a new file to `database/migrations/` with the next number and a descriptive name (e.g. `002_add_sessions.sql`).
2. Run the new migration against existing dev and prod projects (SQL Editor).
3. Run `make db-bootstrap` and commit the updated `database/bootstrap.sql`.
